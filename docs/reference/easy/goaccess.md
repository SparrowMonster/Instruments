# goaccess

**Уровень:** easy · **Назначение:** Web access log analytics.  
**Статус:** справочный материал для предварительной подготовки; не проверен на инфраструктуре соревнования.

## Принцип работы и когда нужен

Web access log analytics. Используй при разборе соответствующих событий на разрешённой инфраструктуре. Для Linux-проверок сначала выполни инвентаризацию сервисов и узнай, какие подключения должны оставаться доступными. Для сетевых систем проверь, видит ли инструмент нужный трафик; для агентов убедись в наличии сервера/сборщика.

## Подготовка и установка

```text
sudo apt install goaccess
```

Перед установкой сверь поддерживаемые версии ОС, зависимости, лицензию и документацию upstream. Не выполняй команду, указанную текстом, как shell-команду.

## Команды и типичные приёмы

```bash
goaccess /var/log/nginx/access.log --log-format=COMBINED
```

**Значение команд:** эти команды позволяют проверить версию и состояние, просмотреть события или выполнить диагностическую проверку. Они не означают, что защита уже включена. Полный CLI и все конфигурационные опции приведены в официальном manual ниже; точный набор флагов зависит от версии.

## Сценарий применения

1. Зафиксируй проблему, время, нужные пользователям функции и исходный ответ сервиса.
2. Установи источник данных: системные журналы, HTTP access logs, пакеты или конфигурации.
3. Выполни доступные read-only проверки, сохрани релевантные результаты без секретов.
4. Сопоставь признаки с обычным поведением; исключи ложные срабатывания.
5. При необходимости выбери минимальное защитное изменение, протестируй на копии.
6. Проверь health-check и ключевую функциональность после изменения.
7. Запиши результаты и затраты CPU/RAM для отчёта.

## Риски

- Безопасность и доступность важнее количества установленных инструментов.
- Настройки блокировки трафика, политики доступа и перезапуски могут нарушить сервис.
- Для сканеров и правил возможны false positives; находка не всегда подтверждает атаку.
- Сохраняй доказательства и не публикуй чувствительные артефакты в открытом репозитории.

## Troubleshooting

Проверь `--help`, версии, доступность логов, полномочия, ресурсы системы, маршруты, разрешённые порты и журнал самого инструмента. Если новый контроль сломал сервис — прекращай дальнейшие изменения и используй заранее проверенный rollback.

## Откат

Восстанови резервную копию изменённых настроек, проверь конфигурацию инструментами соответствующего сервиса, безопасно примени её и повторно проверь штатные функции. Никакого удаления данных наугад.
